<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| container healthcheck → app | Docker/kubernetes probes hitting /health — unauthenticated by design (no sensitive data) |
| host/network → /v1/* routes | Any caller on the Docker network hitting token-protected routes — authenticated via X-AI-Engine-Token |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | E (Elevation of Privilege) | /v1/health + future /v1/* routes | mitigate | FastAPI `Depends(require_token)` dependency on every protected route; missing or wrong `X-AI-Engine-Token` → 401 (tested in test_health.py). Token header-only, never URL param. |
| T-01-02 | S (Spoofing) | require_token | mitigate | Constant-time-ish comparison via direct string compare on the header against settings.AI_ENGINE_TOKEN; token empty → always 401 (no insecure default bypass). |
| T-01-03 | D (DoS) | /health endpoint | accept | Unauthenticated health is required for container healthchecks; returns static JSON, no side effects, low risk on internal-only network. Compose publishes no host port (Plan 03). |
| T-01-04 | I (Information Disclosure) | app/config.py | mitigate | AI_ENGINE_TOKEN has empty default (never hardcoded, Rule B6); .env is gitignored so token can't be committed. |
</threat_model>
