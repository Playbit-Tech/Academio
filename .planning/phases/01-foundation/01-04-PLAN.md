<objective>
Add `AI_ENGINE_URL` + `AI_ENGINE_TOKEN` to the backend config with UNCONDITIONAL fail-fast validation — the FND-04 requirement.

Purpose: The Go↔Python engine seam (Plan 02) is the backbone of ALL future AI traffic (streaming chat, document pipeline) regardless of which LLM provider is selected. FND-04/SC4 requires the backend to fail fast at startup when either var is missing or invalid, per Rule B12. This plan makes the config carry, validate, and expose the two values.

Output: `AIConfig` gains `EngineURL`/`EngineToken`; `validate()` rejects empty/invalid values unconditionally (not gated on `AI_ENABLED`); `AIServiceConfig` + `FromAppConfig` expose them; `.env.example` documents them; local `.env` gets working dev values.

**Decision (resolving the open question flagged in RESEARCH.md):** The check is placed in `validate()` — NOT `validateProduction()`, NOT gated on `c.AI.Enabled`. Rationale: SC4 states "fails fast at startup when AI_ENGINE_URL or AI_ENGINE_TOKEN is missing or invalid" with no AI_ENABLED qualifier, and the seam carries all future AI traffic, so it is required infrastructure like `GOTENBERG_URL`-family config. This means the compose `api` env must also set them (Plan 03 does this) and the config test fixture must include them (updated in this plan).
</objective>

| env vars → config.Load() | Untrusted/missing env crosses into validated startup config here. Missing or malformed values must abort startup (Rule B12) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | E (Elevation of Privilege) | validate() | mitigate | UNCONDITIONAL fail-fast on empty `AI_ENGINE_TOKEN` (no `AI_ENABLED` gate, no default) — a server can never start with an empty service token (Rule B6/B12). |
| T-04-02 | S (Spoofing) | validate() | mitigate | `url.Parse` + scheme whitelist (http/https) + non-empty Host for `AI_ENGINE_URL` — a garbage or scheme-less value (e.g., `not-a-url`) fails startup instead of silently producing a broken client base URL. |
| T-04-03 | I (Information Disclosure) | .env.example | mitigate | Token value in `.env.example` is a dev-only placeholder (`local-dev-token`); `.env` is gitignored (backend/.gitignore:22); production must supply real values via secrets. Comment explicitly states "NEVER a user JWT". |
| T-04-04 | I (Information Disclosure) | AIServiceConfig | accept | EngineToken carried in memory on the config struct — same pattern as existing GeminiAPIKey/OpenAIAPIKey (lines 100-101); no logging of the value anywhere. |
| T-04-05 | D (Denial of Service) | validate() ordering | mitigate | New checks inserted AFTER JWT/Encryption checks — existing negative tests ("missing JWT_SECRET", "missing ENCRYPTION_KEY") keep their asserted error precedence; no test regressions. |
</threat_model>
