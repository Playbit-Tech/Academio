<objective>
Add root CI for the Python engine: `.github/workflows/ai-engine.yml` (FND-05).

Purpose: Every push/PR touching `ai-engine/**` must run ruff lint, pyright type-check, pytest, and a Docker build — and block on any failure. This is the quality gate that keeps the engine skeleton from rotting as later phases add real AI features. The existing backend Go CI lives in the backend submodule repo (`backend/.github/workflows/ci.yml`) and stays untouched — SC5's "existing Go suites stay green" is satisfied because this plan modifies no Go code (Plans 02/04 hold that line and verify Go locally).

Output: A validated root workflow, modeled on the existing `docs.yml` conventions (checkout@v4, `submodules: false`, paths filter, workflow_dispatch), using `astral-sh/setup-uv` (current major v9 — verified via official repo on 2026-07-31, commit pin in RESEARCH.md).

**Key decisions:**
- **`uv sync --frozen`** in every job — Plan 01 commits `uv.lock`; frozen sync makes lockfile drift a CI failure instead of a silent dependency change.
- **`submodules: false`** on checkout — matches docs.yml; the ai-engine/ directory is tracked at root (submodule-ready), so no submodule init needed.
- **One job per concern** (lint / typecheck / test / docker-build) — parallel, and each failure names the exact gate that broke.
- **`working-directory: ai-engine`** on run steps — keeps the workflow readable instead of prefixing every command with `cd ai-engine`.
- **Docker build job** proves the multi-stage Dockerfile (Plan 01 Task 3) works on a clean runner — separate from the uv jobs so base-image pulls don't slow the code gates.
</objective>
