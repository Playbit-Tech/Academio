<objective>
Implement the `ai:doc-ingest` queue worker (D-04, D-09): a handler that loads a pending `ai_documents` row, calls the engine seam exactly once, updates the row's state + quality metrics, sends a ready/failed notification, and records terminal-state metrics.

Purpose: PIP-01 asks for an async pipeline that survives restarts and never silently drops or duplicates a document. The worker is where state transitions (`queued → extracting → chunking → embedding → ready/failed`) and retry semantics live. The row is enqueued by the upload endpoint (04-04) with `asynq.Timeout(6m)` + `asynq.MaxRetry(5)`; the worker side decides PER-ERROR whether to `asynq.SkipRetry` (permanent → failed) or return the error (transient → backoff, D-04). The row insert/state columns come from plan 04-03 (wave 2 — this plan depends on it, so `models.AIDocument` exists at compile time). Handler unit tests still mock the model for isolation (D-10). (Wave swap note: this plan moved from wave 2 to wave 3 so the model/migration plan 04-03 runs first — the handler compiles against a real model, not a promise.)
Output: `TypeDocIngest` task const + payload, `DocIngestTaskHandler` wired into `TaskHandlers`, registration in setup.go, unit tests with a fake engine (D-10), metrics + structured logs per D-09.

Handler logic (strict order — each stage transitions the row so a crash mid-ingest resumes from the last committed state):
1. `json.Unmarshal(t.Payload(), &payload)`; on error → return asynq.SkipRetry (poisoned).
2. Load row: `db.Model(&models.AIDocument{}).Where("id = ?", payload.JobID).First(&doc)`; not-found → return asynq.SkipRetry (row deleted).
3. Transition `doc.Status = "extracting"` + save (100ms ctx timeout — Rule B2; error → return err so retry re-runs; worker restarts re-read the same row — PIP-01 no-duplicate).
4. `aiClient.IngestDocument(ctx, IngestDocumentRequest{DocumentPath: doc.FilePath, Collection: "default", DocumentID: doc.ID, SchoolSchema: "school_" + strconv.FormatUint(doc.SchoolID, 10)})` — exactly ONE engine call per file (PIP-01).
5. Error classification:
```go
var se *engine.StatusError
switch {
case errors.As(err, &se) && se.StatusCode >= 400 && se.StatusCode < 500:
    doc.Status = "failed"; doc.ErrorReason = fmt.Sprintf("permanent: %s", se.Body)
    if uerr := db.Save(&doc).Error; uerr != nil { return fmt.Errorf("mark failed: %w", uerr) } // B9
    logger.Errorf("doc ingest permanent", "job_id", doc.ID, "status", se.StatusCode, "body", se.Body)
    h.recordFailure(doc)  // metric + notification (below)
    return asynq.SkipRetry  // D-04: permanent
default:
    return fmt.Errorf("doc ingest transient: %w", err) // 503/502/network/timeout -> asynq retry/backoff
}
```
6. Success: `doc.Status = "ready"; doc.Pages = resp.Pages; doc.OcrPages = resp.OcrPages; doc.Chars = resp.Chars; doc.Chunks = resp.Chunks` (D-03 quality metrics from the response). Save (error → return err). Then notify + metric.
7. Metrics (D-09): `metrics.QueueProcessedTotal.WithLabelValues(TypeDocIngest, "success"/"failed").Inc()`; `metrics.QueueFailedTotal.WithLabelValues(TypeDocIngest).Inc()` for failures. All metrics at terminal states (queued/extracting/chunking/embedding are NOT emitted — no partial-signal).

Notification (D-08, best-effort): on ready → `h.notifications.Create(ctx, nil, doc.UploadedBy, doc.SchoolID, "Document ready", fmt.Sprintf("Document %q is ready to search.", doc.FileName), "ai_document")`; on failed → "Document processing failed: <reason>". `Create` with a nil tenantDB is fine — it broadcasts via the hub. Log a warning on error (B9: log-and-continue for notifications).
9. All status writes pass `ctx` with the 100ms timeout; never `context.Background()` (Rule B2).</action>
