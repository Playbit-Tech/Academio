<objective>
Create the shared/public `ai_documents` status table (D-01, D-03) and its GORM model, registered in the CORE migration chain.

Purpose: D-01 places the ingest STATUS table in the shared `public` schema (not a tenant schema) because the queue worker (04-02) is not tenant-scoped — it must update status without a tenant DB handle, and the upload endpoint needs a school-scoped identity for listing. D-03 defines the 5-state enum + quality metrics (pages, ocr_pages, chars, chunks) stored on the row. The `id` is a UUID that doubles as the engine `document_id` (D-02) and the enqueue JobID (04-02). This plan is intentionally placed BEFORE the worker: it is wave 2 so the `models.AIDocument` row contract exists at compile time when the worker (04-02, wave 3) and the endpoints (04-04, wave 4) implement against it. (Wave swap note: this plan was formerly planned as wave 3 after the worker; it moved to wave 2 ahead of the worker per the dependency-correctness fix — the model must exist before the handler compiles against it.)
Output: `AIDocument` model in `backend/internal/database/models/`, a NEW core migration file `ai_documents.go`, and registration in `core.go` — with the existing `core/ai.go` migration UNTOUCHED.
</objective>
