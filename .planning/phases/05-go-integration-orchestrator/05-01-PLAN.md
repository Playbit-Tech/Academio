<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client→API | Untrusted input crosses here (AI endpoint requests) |
| API→orchestrator | Trust boundary where enforcement occurs |
| orchestrator→Python service | External service call requiring protection |
| Python service→LLM | External API call (handled by Python) |
| orchestrator→Redis | Trusted infrastructure (rate limit, quota, cache) |
| orchestrator→Postgres | Trusted infrastructure (cost ledger) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | S (Spoofing) | Rate limiter keys | mitigate | Validate school_id (uint) and scope (enum) before constructing Redis keys; never include raw user strings in keys |
| T-05-02 | T (Tampering) | Quota counters | mitigate | Use Redis INCRBY as atomic counter; avoid GET→SET read-modify-write patterns |
| T-05-03 | I (Information Disclosure) | Cost ledger | mitigate | Table in public schema (shared) but no PII - only school_id, user_id (both non-PII identifiers), usage metrics; audit trail (B11) handles who did what separately |
| T-05-04 | D (Denial of Service) | Rate limit bypass | mitigate | Per-school hard guard ai:rl:{scope}:{school_id} prevents noisy school starvation; sliding window limiter provides built-in retry-after |
| T-05-05 | E (Elevation of Privilege) | Cache key injection | mitigate | Tenant-scoped keys always include school_id; validate/escape components before hashing prompt+model with SHA-256 |
| T-05-06 | D (Denial of Service) | Cache stampede | mitigate | Short TTL values (15s-10min) prevent long-lived cache entries; log-and-continue on Redis write failures prevents request failure |
</threat_model>
