## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | S (Spoofing) | Provider status response | mitigate | Status values are controlled enums (healthy/degraded/unavailable/cooldown/open/half_open/closed) — no user input |
| T-05-02 | T (Tampering) | Cooldown timestamps | mitigate | CooldownUntil derived from breaker state and Python cooldown_until; both server-side controlled |
| T-05-03 | I (Information Disclosure) | Provider health details | mitigate | No internal IPs, ports, or secrets exposed; only provider name, status, and latency |
| T-05-04 | D (Denial of Service) | /v1/providers call failure | mitigate | Python health check failure is log-and-continue (B9); cached status served if available |
| T-05-05 | E (Elevation of Privilege) | Cache key construction | mitigate | Cache key uses school_id (uint) and fixed endpoint name; no user strings |
| T-05-06 | D (Denial of Service) | Cache stampede on providers | mitigate | 15s TTL prevents long-lived cache entries; log-and-continue on Redis failure |
</threat_model>
