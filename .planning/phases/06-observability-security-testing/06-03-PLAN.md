<objective>
Implement the RAG evaluation harness (TES-01): a hermetic pytest suite in ai-engine/tests/rag_eval/ with a golden set of 50-100 school-realistic QA pairs, deterministic context-precision scoring, LLM-judge faithfulness scoring (stub for hermetic CI), gates faithfulness ≥0.85 and context precision ≥0.75, and a CI workflow (rag-eval.yml) that runs it on every chunking/embedding/prompt change.

<threat_model>
- False-positive eval: golden answers must be seeded into the SAME corpus the harness queries (no external/private answers); a test that passes by hitting a pre-baked in-memory result instead of the real hybrid SQL would be false verification — assert the harness runs the REAL ingest → chunk → embed → store → hybrid search path (monkeypatch only the embedding model, as test_search.py does).
- Leaky golden set: golden.jsonl must not contain the exact answer text that the corpus stores verbatim in a way that trivializes retrieval (use paraphrase-style expected_answer_fragments).
- CI flakiness: judge stub must be deterministic; real judge runs nightly (deferred — not in CI).
</threat_model>

<task type="auto">
  <name>Task 2: Eval harness — conftest + scoring</name>
  <files>ai-engine/tests/rag_eval/conftest.py, ai-engine/tests/rag_eval/test_rag_eval.py</files>
  <action>
    Create ai-engine/tests/rag_eval/conftest.py:
    - `def corpus_docs() -> list[dict]` — 6-10 short school-topic documents (plain text) that the golden set references (doc1, doc2, ... docN).
    - `def judge_stub(question, retrieved_chunks, expected_fragments) -> float` — deterministic faithfulness scorer used in CI: returns 0.9 if at least 2 expected_answer_fragments appear in the retrieved chunks' text (case-insensitive substring), 0.6 if at least 1, else 0.3. This is the hermetic CI judge.
    - `def run_retrieval(schema_name, question) -> list[str]` — runs the REAL pipeline: ingest corpus_docs into a seeded tenant schema via ingest_document (same DB-gated pattern as test_search.py: skip if AI_PGVECTOR_DSN unset), then hybrid search, returning the top-K chunk texts (or chunk ids + texts). Monkeypatch only the embedding provider (stub embed as test_search.py does with VECTOR_1536) so the real hybrid SQL runs deterministically.
    - Fixture `eval_corpus` that seeds the docs once per session and cleans up.

    Create ai-engine/tests/rag_eval/test_rag_eval.py:
    - `test_context_precision_gate`: for each golden entry, compute context precision = |expected_sources ∩ retrieved_sources| / |expected_sources|; assert mean >= 0.75 across the golden set.
    - `test_faithfulness_gate`: for each golden entry, faithfulness = judge_stub(question, retrieved_chunks, expected_fragments); assert mean >= 0.85.
    - `test_hermetic_no_live_key`: assert the suite runs with the embedding provider stubbed and no live AI_OPENAI_API_KEY requirement (mirror test_search.py skip logic).
    - Mark the DB-gated tests with the LIVE_DB skipif pattern from test_search.py (skip when AI_PGVECTOR_DSN unset) EXCEPT the hermetic ones that don't need DB.
  </action>
