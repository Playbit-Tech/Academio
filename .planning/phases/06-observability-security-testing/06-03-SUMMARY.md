## Decisions Made

- **Single source of truth for corpus + golden.** A hand-pasted corpus block in conftest had drifted from the generator (inserted spaces between sections, trimmed filler) — byte offsets shifted, so fragment-driven chunk refs pointed at the wrong chunks (35 window failures + 3 out-of-range refs during verification). The generator is now committed as `tools/corpus_gen.py` and conftest imports `CORPUS` from it; a hermetic containment test guards alignment forever.
- **Vocab-table embedding instead of md5 hash.** The md5-based `_keyword_vector` produced collision noise (e.g. the chloroplast query ranked math/shakespeare chunks above the biology answer — 3 genuine retrieval misses). The vocab table maps each of the corpus's 965 stopword-filtered tokens to a unique dim (< 1536-dim contract) → cosine similarity is exact content-token overlap → dense and BM25 legs agree on the answer chunk.
- **Fractional faithfulness judge.** The planned 0.9/0.6/0.3 step function caps all 33 one-fragment questions at 0.6, making the 0.85 mean gate unreachable (max ≈0.725). `hits / len(expected_fragments)` puts single-fragment entries on the same 0..1 scale and is the standard fragment-based faithfulness measure.
- **Session-scoped autouse embedding patch.** Function-scoped monkeypatch raced the session-scoped `seeded_corpus` ingest (session fixtures set up before per-test fixtures) → real `EmbeddingClient` → `EmbeddingNotConfiguredError`. Manual setattr/restore (monkeypatch is function-scoped only) fixes the ordering.
- **`pythonpath = ["."]` in pyproject.** pytest's basedir chain never reached the ai-engine root for `app.*` imports because `tests/rag_eval` has no `__init__.py`; explicit pythonpath fixes collection.
